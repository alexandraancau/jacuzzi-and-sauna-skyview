# Components

## Purpose

The Skyview component library is designed to create a calm, elegant and consistent experience across the website.

Components should feel invisible.

They should support the content, never compete with it.

---

# Core Principles

Every component should be:

- Simple
- Consistent
- Accessible
- Reusable
- Timeless

When in doubt, choose the simpler solution.

---

# Buttons

## Primary Button

### Purpose

Used for the most important action on the page.

Examples:

- Book now
- Check availability
- Reserve your stay

### Style

- Signature Plum background
- Warm Ivory text
 - Warm Ivory text
 - Refined rectangular corners: 6px border radius (use `radius.small` token)
- Comfortable horizontal padding

### Rules

- Only one primary button per section.
- Never place two competing primary actions next to each other.

---

## Secondary Button

### Purpose

Secondary actions.

Examples:

- Learn more
- View gallery
- Contact us

### Style

- Transparent background
- Deep Graphite border
- Deep Graphite text

---

## Text Button

Used inside paragraphs or cards.

Should never become the main CTA.

---

# Cards

Cards group related information.

### Style

- Warm Ivory background
- Large border radius
- Soft shadow
- Generous padding

Cards should feel lightweight.

Avoid heavy borders.

---

# Navigation

The navigation should disappear into the experience.

### Rules

- Minimal links
- Clear hierarchy
- Always visible booking action
- Responsive on all devices

---

# Hero Section

The hero introduces the emotional experience.

It is not a promotional banner.

### Includes

- Large photography
- Short headline
- Small supporting paragraph
- Primary CTA

Avoid:

- Multiple CTAs
- Long paragraphs
- Information overload

---

# Section Layout

Every section follows the same rhythm.

### Recommended spacing

Top:

80–120px

Bottom:

80–120px

Content width:

1200px maximum

---

# Images

Photography is always the hero.

### Rules

- Large images
- Natural light
- No heavy filters
- Rounded corners only where appropriate

Images should communicate emotion before information.

---

# Forms

Forms should feel effortless.

### Rules

- One column layout
- Clear labels
- Minimal required fields
- Helpful validation messages

---

# Icons

Icons support understanding.

They never replace text.

### Style

- Simple
- Thin
- Rounded
- Consistent stroke width

---

# Dividers

Dividers should be subtle.

Prefer whitespace before adding lines.

---

# Shadows

Use shadows sparingly.

The goal is depth, not decoration.

---

# Border Radius

Rounded corners should feel soft and modern.

Use the same radius consistently across the interface.

---

# Empty States

Every empty state should reassure the user.

Never leave blank screens.

---

# Loading States

Loading should communicate progress calmly.

Avoid distracting animations.

---

# Error Messages

Error messages should be:

- Clear
- Human
- Actionable

Never blame the user.

---

# Success Messages

Celebrate quietly.

Confirmation should feel reassuring rather than exciting.

---

# Responsive Behaviour

Components should adapt naturally across devices.

Prioritize readability over density.

---

# Accessibility

Every interactive component must:

- Be keyboard accessible.
- Include visible focus states.
- Meet WCAG AA contrast requirements.
- Be usable without relying only on color.

---

# Component Checklist

Before creating a new component, ask:

- Is it reusable?
- Is it accessible?
- Is it consistent with existing components?
- Does it simplify the experience?
- Does it help guests unwind?
